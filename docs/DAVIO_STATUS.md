# DAVIO — состояние реализации

Актуальная задача: развитие `avito-seller` от `2cc257d`, ветка `work`. Это продолжение прежнего приложения, без удаления старого каталога/диалогов/обучения/медиа. Код новой версии располагается в тех же Next.js App Router, `components/davio` и `lib/davio`.

## Хранение и границы доступа

- `lib/davio/server/db.ts`: встроенная SQLite Node 24, WAL, foreign keys, короткие транзакции `BEGIN IMMEDIATE`, prepared statements. Дополнительный платный/облачный сервис для запуска не нужен.
- Реально используемые таблицы: users, sessions, projects, revisions, files, project_files, jobs, usage, plans, rate_limits, chat, runtime. `schema/saas-reference.sql` остаётся эталоном предыдущего этапа, не схемой текущей серверной БД.
- Исходники, JPEG и MP4 — приватные BLOB, не URL в `public`. Каждое чтение требует сессии и соответствия владельцу; администратор не получает исключение для доступа к чужим файлам.
- Пароли: scrypt N=32768 со случайной солью, сравнение constant time. Случайный токен сессии 256 бит; БД хранит SHA-256 токена. HttpOnly, SameSite=Strict, 7 дней. `Secure` включается при `DAVIO_APP_ORIGIN=https://…`.
- Все изменяющие API требуют совпадающий Origin. В доверенной прокси-установке укажите точный `DAVIO_APP_ORIGIN`; произвольным X-Forwarded-Host доверия нет.
- Проверяются размер JSON/файлов, декодирование изображений, лимит пикселей, частота запросов, размер хранилища и число исходников. Одновременно в одном веб-процессе обрабатываются максимум две фотографии. Видеозадач у пользователя может быть не более двух незавершённых.
- Правки текста используют отдельный номер версии, принятый при загрузке/сохранении текста. Обновление списка файлов и опрос видеозадачи не принимают чужую версию текста. Конфликт — HTTP 409 с сохранением локального ввода.
- Sharp не меняет оригинальный файл. Каждая обработка создаёт независимый JPEG с `sourceId` и точными параметрами коррекции/размера/качества. Настройки видео также записываются в метаданные готового файла и в параметры задания. Старые записи получают пустые настройки через добавление колонки, без удаления байтов. Версии текста восстанавливаются без удаления или регенерации медиа.
- Кнопка архива не выполняет DELETE. Убранный из объявления исходник остаётся в files, но не в активном списке; физическое удаление/восстановление такого скрытого исходника пока не реализовано. Это занимает квоту.
- Старые браузерные данные Seller AI сохраняют исходные ключи. Они доступны через явно обозначенные «Прежние локальные инструменты» и не являются серверными приватными данными нового аккаунта. Автоматического переноса нет.

## Очередь FFmpeg

`npm run worker` выполняется отдельно от Next.js, с тем же `DAVIO_DATA_DIR`. `.env.local` загружается обоими процессами. Один worker на одну SQLite-БД; heartbeat каждые 3 секунды. Второй свежий worker отказывается запускаться. После аварии предыдущая `processing`-задача становится ошибочной при следующем запуске; пользователь может повторить. Очередные задачи сохраняются в БД.

Каждое задание содержит снимок ID фото, формата, длительности и подтверждённого названия. FFmpeg принимает только локальные нормализованные PNG и текстовый файл титра. Пользовательский текст не вставляется в командную строку фильтра; shell не используется. На этап установлены таймауты. Временные файлы создаются в отдельном случайном каталоге и очищаются после задачи. Результат пишется в приватную БД только после успешного монтажа.

Не запускайте этот worker в serverless-функции Vercel. Для текущей версии нужен процесс Node 24 с постоянным диском и установленным FFmpeg. Vercel может использоваться в будущем для соответствующих веб-компонентов после переноса БД/медиа/очереди; текущую локальную SQLite-сборку нельзя выдавать за готовую Vercel-архитектуру.

## Подключение будущих API

1. Выберите официальный провайдер и проверьте актуальные модели, цены, регион и права. Получите отдельное разрешение владельца на расходы и передачу данных.
2. Добавьте серверный адаптер `ContentAIProvider` из `lib/davio/integrations.ts` для описаний/vision и `GenerativeMediaProvider` из `lib/media/types.ts` для генеративного медиа. Сейчас это контракты, не скрыто работающие интеграции.
3. Ключи задавайте только серверными env, без `NEXT_PUBLIC_`, без Git и без localStorage. Добавьте allowlist endpoint, таймаут, отмену, ограничение параллелизма, учёт usage и потолок расходов. Не разрешайте браузеру передавать произвольный URL модели.
4. Подключите только разрешённые функции в серверном каталоге возможностей. Сохраняйте источник предложения и обязательное подтверждение критических характеристик. Генерация текста не должна заменять обработанные фото и видео.
5. Для существующей лаборатории сравнения готовые серверные адаптеры Yandex/DeepSeek/Qwen/GigaChat и конфигурация моделей описаны в `SELLER_AI.md`. Реальные запросы требуют `SELLER_AI_ENABLE_REAL=true`, ключей, отдельного кода доступа и проверенных model ID. Ничего из этого в текущей задаче не включалось.
6. Официальные маркетплейс-адаптеры реализуются отдельно от продукта через `MarketplaceAdapter`; сейчас доступен ручной экспорт. Публикация/отправка сообщений требуют доступного официального API, прав и подтверждения пользователя. Обход авторизации и скрытый парсинг не используются.
7. Биллинг: цены решает владелец; подключение ЮKassa или другого провайдера потребует серверных подписанных/idempotent webhook, проверок суммы/валюты/статуса и отдельного согласования. Текущий PRO — набор лимитов, не оплаченная подписка.

## Что ещё нужно до публичной эксплуатации

PostgreSQL и миграции, приватное object storage, внешняя очередь/несколько worker с lease fencing, резервное копирование/восстановление, централизованные лимиты между репликами, мониторинг и эксплуатационные лимиты CPU/памяти/диска. Почтовая верификация, восстановление доступа, управление отдельными сессиями, правила регистрации, аудит административных действий и отдельный security-review. HTTPS с правильным Origin/Secure, ограничения reverse proxy на размеры/таймауты, защита от злоупотреблений. Проверка персональных данных/локализации хранения и договоров с провайдерами для российского рынка; это не юридическое заключение.

Текущий worker — надёжный базовый локальный процесс с одной очередью, не коммерческий распределённый кластер. Содержимое SQLite не шифруется приложением: защищайте диск и резервные копии. Никакого production-деплоя, покупки доменов, платежей, внешних аккаунтов, публичного туннеля и автоматических отправок в рамках задачи не выполняется.
