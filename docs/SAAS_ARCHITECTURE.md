# Границы текущей версии и путь к SaaS

Сейчас это локальное пространство одного владельца, а не защищённая многопользовательская платформа. Данные разделены по магазину в браузере, но это не защита от другого человека, имеющего доступ к тому же браузерному профилю/DevTools. Фиктивной регистрации и оплаты нет.

## Уже работает

- Реестр до 30 локальных магазинов с отдельными каталогами, переписками, AI-настройками, чатом, лабораторией, примерами, объявлениями и медиа.
- Привязка TrainingExample к workspace/store/product, исходный и исправленный ответ, статус, комментарий, даты и история версий.
- Контекстный поиск только одобренных примеров текущего магазина и товара. Это справка; данные сами не отправляются внешней LLM.
- Серверная защита реальных запросов сравнения из предыдущего этапа: opt-in, отдельный код владельца, ограничение размеров/частоты/времени, серверные ключи. Она рассчитана на одного владельца, не заменяет вход пользователей и tenant authorization.
- Черновики объявлений и реальные локальные медиаоперации. Для генеративных провайдеров подготовлен контракт; подключения нет.
- Аналитика локальной работы с честным пустым состоянием для продаж/конверсии. Субъективное одобрение не превращается в доказательство эффективности.

## Подготовленные серверные границы

`lib/platform/access.ts`: User principal, memberships с ролями owner/admin/editor/viewer, проверка прав на конкретный магазин, контракт официального MarketplaceAdapter, UsageRecord и SubscriptionPlan. Principal должен формироваться серверной сессией/проверенным токеном, никогда не приниматься из JSON браузера.

`lib/platform/automation.ts`: изолированный planner проверяет права, официальное подключение, отдельное разрешение, глобальное включение, вмешательство человека, дубликаты по идентификатору входящего сообщения, разрешённый сценарий и частоту. Он ничего не отправляет. Сохраняемые настройки интерфейса принудительно имеют autoEnabled=false. Смена режима в интерфейсе не включает отправку.

`schema/saas-reference.sql`: проверенная на in-memory SQLite эталонная схема Users, Workspaces, Memberships, Stores, Products, Conversations, Messages, AI Settings, Training Examples/Revisions, Listings, Media Assets, Generation Jobs, Usage Records, Plans, Subscriptions и Audit. Составные foreign keys не допускают ссылок между магазинами. Это документация будущего серверного хранилища, не выполненная миграция пользовательских данных. Денежных тарифов и оплаты в схеме нет.

## Следующий серверный этап перед тысячами пользователей

1. Настоящий вход, восстановление доступа, защищённые серверные сессии, memberships, CSRF и аудит. Тесты отрицательных разрешений для каждого API и job.
2. Серверная БД и репозитории с обязательным workspace/store scope. Миграция локальных данных только по согласию пользователя: экспорт/проверка/импорт с сохранением ID, без удаления браузерного источника. Единая серверная модель товара объединит каталог и знания; сейчас это самостоятельные копии.
3. Приватное объектное хранилище, подписанные временные URL, квоты, антивирус/декодирование медиа и удаление по подтверждению. Сырые Blob не хранятся в localStorage.
4. Долговечная очередь, блокировка/lease job, idempotency keys, retries с backoff только для безопасных действий, cancellation, дедупликация входящих webhook. Глобальные лимиты и бюджеты в БД/Redis, а не памяти процесса.
5. Серверный OAuth доступной официальной интеграции Авито. Ограниченные scopes, секреты в secret manager, отдельные разрешения на отправку, ручная остановка. Ни scraping, ни обходов ограничений.
6. Одобренные примеры добавлять в prompt только после авторизации доступа и явного разрешения на отправку данных провайдеру; они не могут отменять актуальные факты и правила безопасности. Оценка модели не гарантирует отсутствия галлюцинаций.
7. Учёт каждого внешнего вызова до/после ответа, неизвестного usage при разрыве, тарифов/версий/валют, лимитов бюджета. Платежи и тарифы — отдельное согласование.
8. Настоящая административная панель платформы с отдельной серверной ролью, аудитом и принципом минимальных прав; нынешние настройки владельца не являются такой панелью.

## Производительность и ограничения

Медиа- и новые функциональные разделы загружаются динамически. Object URL, MediaStream, requestAnimationFrame, таймеры и AbortController освобождаются. Реальные локальные операции требуют открытого браузера; они не являются фоновой облачной очередью. Прерывание отображается как ошибка с сохранением исходников. Очистка данных браузера может удалить весь локальный контент — нужен экспорт, затем серверные резервные копии.

Пределы: обучение 1000 примеров и до 100 сохранённых предыдущих версий на пример; чат до 200 тестовых обменов; 200 черновиков объявлений и 200 медиа-заданий; фото 8 МБ/25 Мп, видео 30 МБ, до 10 исходников, локальное видео 3–30 секунд. Браузерная квота может оказаться ниже этих верхних пределов: приложение показывает ошибки хранения. При достижении лимита примеров/версий данные не удаляются автоматически.
