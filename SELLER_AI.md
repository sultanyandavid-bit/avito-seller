# AI-продавец: лаборатория сравнения

Новый модуль в существующем Seller AI: `/seller`. Старый `/assistant`, каталог, сообщения и настройки сохранены.

## Как попробовать

1. Откройте **AI-продавец → База знаний**. В базе уже есть демонстрационные велосипед и горнолыжный костюм. Отредактируйте подтверждённые факты, доставку, скидки и инструкции. Пустые поля означают неизвестные условия.
2. Во вкладке **Тестирование AI** выберите товар, затем сценарий или свой вопрос. Для костюма выберите соответствующий товар вручную.
3. Оставьте режим **Демонстрация** и два выбранных локальных алгоритма. Нажмите **Запустить демосравнение**.
4. Сравните тестовые ответы и раскройте **Оценить ответ вручную**. Каждый из семи критериев можно оценить от 1 до 5, оставить без оценки и добавить комментарий. Автооценок и утверждений об эффективности продаж нет.
5. Откройте **История тестов**: ответы, субъективные оценки и снимки товарных данных сохраняются после перезагрузки. Изменение или удаление карточки знаний не меняет старые тесты. Доступен экспорт JSON и подтверждаемая очистка истории.

У демо нет API-токенов и стоимости: показано «Не применяется». Время — фактическое время локального алгоритма на сервере, не скорость реальной модели. Два варианта отличаются оформлением одного алгоритма. Это не результаты Yandex, DeepSeek, Qwen или GigaChat. Произвольные инструкции продавца сохраняются и показываются как правила, но демоалгоритм не интерпретирует их как LLM. Ответы никому не отправляются.

Карточки знаний независимы от старого каталога. Из каталога можно создать копию; дальнейшей автоматической синхронизации нет. Данные лаборатории используют отдельный ключ `seller-ai:lab:v1`; данные прежнего MVP `ai-avito-seller:v1` не мигрируют и не перезаписываются. Сброс старого демомагазина не сбрасывает лабораторию.

## Переписки и свои сценарии

Сценарий содержит текущий вопрос и контекст до него. Сохраните его под своим именем. Поддерживаются TXT и JSON до 100 КБ, до 20 сообщений; до 2000 символов на сообщение и 12000 на контекст. Последнее сообщение должно быть от покупателя и становится текущим вопросом. Общая история лаборатории ограничена 50 последними запусками, база и сценарии — 100 записями каждого вида. При переполнении браузерного хранилища появляется предупреждение; экспортируйте историю.

TXT:

```text
Покупатель: Велосипед ещё продаётся?
Продавец: Здравствуйте, да.
Покупатель: А скидку сделаете?
```

JSON:

```json
[
  { "role": "buyer", "text": "Здравствуйте, костюм есть?" },
  { "role": "seller", "text": "Да, размер M." },
  { "role": "buyer", "text": "Подойдёт для -20?" }
]
```

Удалите персональные данные из переписки до загрузки. В деморежиме сервер приложения обрабатывает её локально; реальные API получат выбранную карточку, контекст и вопрос только после явного запуска реального сравнения. API-ключи не передаются в браузер.

## Будущее подключение реальных API

Реальные запросы не запускались. В коде нет встроенных идентификаторов реальных моделей или тарифов. Каталог строится из серверной конфигурации. Наличие записи не доказывает доступ к модели у провайдера: проверьте ID, регион, разрешения и тариф в своём аккаунте по официальной документации.

После получения ключей **и отдельного разрешения владельца на расходы**:

1. Скопируйте `.env.example` в `.env.local`. Не коммитьте `.env.local`.
2. Заполните переменные только нужного провайдера:
   - Yandex AI Studio: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. Адаптер использует Api-Key и OpenAI-Project, модель — полный ID из вашего каталога.
   - DeepSeek: `DEEPSEEK_API_KEY`.
   - Qwen через Alibaba Cloud Model Studio: `QWEN_API_KEY`, `QWEN_BASE_URL`. URL из документации вашего workspace/региона, с окончанием `/compatible-mode/v1`. Ключ должен соответствовать региону. Разрешены только HTTPS workspace-домены `*.{region}.maas.aliyuncs.com` из проверенного списка регионов.
   - GigaChat: `GIGACHAT_ACCESS_TOKEN` — действующий короткоживущий OAuth-токен. Постоянный Basic Authorization key сюда не подходит. В этом этапе автоматический обмен/обновление OAuth не реализован; при истечении получите новый токен по официальной инструкции и перезапустите сервер. TLS-проверка не отключается: при необходимости установите официальную цепочку доверия на сервере.
3. Заполните `SELLER_AI_MODELS` JSON-массивом. Каждая запись: `provider` (`yandex`, `deepseek`, `qwen`, `gigachat`), точный `id`, понятный `label`. Пример структуры с **плейсхолдером**, который необходимо заменить, а не отправлять провайдеру:

```dotenv
SELLER_AI_MODELS='[{"provider":"deepseek","id":"<ID_ИЗ_ОФИЦИАЛЬНОГО_КАТАЛОГА>","label":"Модель из моего аккаунта"}]'
```

4. При необходимости добавьте в запись `tariff`: числовые `inputPerMillion` и `outputPerMillion`, `currency` (RUB, USD, EUR или CNY), `source` (HTTPS-ссылка на проверенный тариф). Цены не заполнены намеренно. При отсутствии тарифа или usage стоимость остаётся неизвестной. Расчёт: `(inputTokens × inputPerMillion + outputTokens × outputPerMillion) / 1 000 000`. Валюты не конвертируются и суммируются отдельно. Это приближение по заданным ставкам, без кеширования, специальных категорий токенов, скидок и налогов; сверяйте счёт провайдера.
5. Создайте независимый случайный `SELLER_AI_ACCESS_TOKEN` длиной минимум 32 символа. Это код администратора для защиты расходов приложения, не API-ключ провайдера. Например, сгенерируйте его локально: `openssl rand -hex 32`. Храните только в `.env.local` или менеджере серверных секретов.
6. Только после разрешения установите `SELLER_AI_ENABLE_REAL=true` и перезапустите сервер. Откройте **Реальные модели**, выберите до четырёх настроенных моделей и введите код администратора. Код хранится только в памяти компонента и очищается при перезагрузке/уходе с вкладки. Запросы инициируются вручную.

Если ключи, код или обязательные настройки отсутствуют, модели остаются недоступными. Неизвестный ID возвращает безопасную ошибку провайдера; интерфейс не имитирует успешное подключение. Список моделей определяется конфигурацией администратора, а не автоматическим платным или аутентифицированным запросом при открытии страницы.

Проверенные первоисточники (16 октября 2026, МСК):

- [Yandex AI Studio: базовый Completions-запрос](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-basic).
- [DeepSeek: Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/).
- [Qwen / Alibaba Cloud: OpenAI-compatible API](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope).
- [GigaChat: адрес API, OAuth и авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

Протоколы и региональные адреса могут меняться. Обновляйте адаптер и конфигурацию по документации перед реальным подключением.

## Серверная архитектура и ограничения

`GET /api/seller/providers` возвращает только публичные параметры моделей и состояния конфигурации. Секретов в ответе нет, проверочных обращений к провайдерам нет.

`POST /api/seller/compare` проверяет JSON, origin, размеры, карточку, сценарий и 1–4 уникальных модели. Для реального режима нужны серверный opt-in и Bearer-код администратора (проверка через timingSafeEqual). Демо не может вызвать реальные модели. Ключи и сетевые адреса провайдеров из тела запроса не принимаются. Redirect запрещён, TLS-проверка включена. Текст внутренних исключений и сырые ошибки провайдеров клиенту не отправляются.

Лимиты MVP на один серверный процесс:

- Запрос приложения до 64 КБ, ответ провайдера до 256 КБ.
- До двух одновременно выполняющихся сравнений и четырёх моделей в каждом.
- Демо: до 60 сравнений в минуту.
- Реальные попытки: до 12 модельных запросов в минуту и 60 в час.
- Таймаут провайдера 15 секунд, максимум 700 выходных токенов, без автоматических повторов. Интерфейс прекращает ожидание через 25 секунд.

Ошибки одной модели не скрывают ответы других. В истории сохраняется начальная запись перед обращением к серверу; при прерывании или ошибке расход отмечается как неизвестный. Токены берутся из фактического API usage, а не оцениваются по длине текста. Для ошибок API может выставить счёт даже без возвращённого usage. Блок расходов показывает только сохранённую историю текущего браузера, не весь биллинг аккаунта.

Для будущих провайдеров расширяются реестр `providerAdapters`, серверная конфигурация и тип провайдера; компоненты сравнения и оценок не зависят от транспорта. Системный промпт передаёт карточку как данные, запрещает выдумки и отделяет роли контекста. Это инструкция модели, а не доказанная защита от галлюцинаций: все реальные ответы — непроверенные черновики.

Перед многопользовательской эксплуатацией нужны авторизация по пользователям/магазинам, серверная БД, аудит каждого внешнего обращения, распределённые лимиты/бюджеты и очередь. Текущие лимиты сбрасываются при рестарте процесса, история локальна, OAuth GigaChat обновляется вручную. Не размещайте режим реальных расходов в публичном доступе без этого этапа.

## Запуск на MacBook

Из существующего checkout проекта (Node.js 24 LTS):

```bash
cd avito-seller
npm ci
npm run dev
```

Откройте http://localhost:3000/seller в Chrome, не закрывая Терминал. Если checkout старее новых изменений, сначала перенесите/сохраните эту версию кода. Для production: `npm run build`, затем `npm start`. Переменные окружения не нужны для деморежима. `localhost` работает на компьютере, где запущен сервер; облачный порт без приватного проброса на MacBook недоступен (см. `PREVIEW.md`).

Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, затем `npm run test:e2e` (предварительно `npx playwright install chromium` или системный `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`).
